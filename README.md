# کیت ساخت RustDesk برندشده (مستقل، بدون نیاز به نصب)

خروجی: یک فایل `exe` تکی با نام، لوگو و مشخصات شرکت شما، که از قبل به سرور و کلید شما وصل است.

## مراحل

1. در GitHub مخزن رسمی `rustdesk/rustdesk` را **Fork** کنید (ترجیحاً Private نگه دارید).
   برای تطابق با تست ما، نسخه `1.5.3` (commit `54416dc`) را بسازید؛ نسخه‌های جدیدتر ممکن است نیاز به تنظیم دوباره داشته باشند.
2. محتویات این کیت را در ریشه فورک آپلود کنید:
   پوشه `brand/` و فایل `.github/workflows/build-brand-windows.yml`.
3. پوشه `brand/assets/` (شامل آیکن و لوگوی آماده شرکت دستیار) و پوشه `brand/dart/` را آپلود کنید.
4. فایل `brand/brand.json` را ویرایش کنید:
   `app_name` (نام نسخه پشتیبان) و `customer_app_name` (نام نسخه مشتری، مثل `DastyarHelp`؛ فقط حروف انگلیسی)، `company_name`، `copyright`، `website`، `privacy_url`.
   در مقادیر از علامت نقل‌قول، `\` و `$` استفاده نکنید.
5. در مخزن: Settings ← Secrets and variables ← Actions ← دو Secret بسازید:
   - `RENDEZVOUS_SERVER` : فقط آدرس یا IP سرور شما، بدون پورت
   - `RS_PUB_KEY` : محتوای فایل `id_ed25519.pub` سرور
6. تب Actions ← `Build branded Windows client` ← Run workflow. در فیلد `mode` یکی را انتخاب کنید:
   - `support`: نسخه کامل برای شما (اتصال به مشتری)
   - `customer`: نسخه مشتری (فقط نمایش ID و رمز، بدون امکان اتصال به جای دیگر)
   برای ساخت هر دو، workflow را دو بار اجرا کنید.
7. پس از اتمام (حدود ۴۰ تا ۶۰ دقیقه یا بیشتر) از بخش Artifacts فایل `branded-windows-exe-support` یا `branded-windows-exe-customer` را دانلود کنید.

اگر فورک شما نسخه دیگری از RustDesk دارد، فایل workflow را دوباره بسازید:
`python3 make_workflow.py .github/workflows/flutter-build.yml .github/workflows/build-brand-windows.yml`

## اسکریپت چه چیزهایی را تغییر می‌دهد
- آدرس سرور و کلید عمومی پیش‌فرض (داخل کد)
- نام برنامه، نام شرکت، کپی‌رایت، توضیح فایل (Properties ویندوز)
- لینک‌ها و نام شرکت در صفحه About
- متن‌های ترجمه‌شده (نام RustDesk ← نام شما)
- آیکن‌ها و لوگو
- غیرفعال‌سازی پیشنهاد به‌روزرسانی از سرورهای RustDesk

اگر کد RustDesk تغییر کرده باشد و الگویی پیدا نشود، اسکریپت با پیام خطا متوقف می‌شود (بدون ساخت نسخه ناقص).

## نکات مهم
- **صحت‌سنجی:** اسکریپت‌ها روی کپی سورس تست شدند، ولی ساخت کامل روی GitHub Actions اجرا نشده است. اگر خطایی دیدید لاگ را بفرستید.
- **مجوز AGPL-3.0:** در صورت توزیع نسخه تغییر‌یافته به مشتریان، باید سورس تغییرات را در اختیار آن‌ها قرار دهید (همین فورک کافی است).
- **نام تجاری:** نام و لوگوی RustDesk را در `app_name` و لوگو استفاده نکنید.
- **امضا:** فایل بدون امضای دیجیتال است و ممکن است SmartScreen هشدار بدهد.
- **محدودیت نسخه Portable:** نصب سرویس و دسترسی بدون نظارت (Unattended) و عبور از UAC فقط با نصب کامل در دسترس است. برای پشتیبانی لحظه‌ای کافی است.
- **هزینه:** مخزن Private از دقیقه‌های Actions مصرف می‌کند (ویندوز ۲ برابر). مخزن Public فایل `brand.json` را نمایش می‌دهد؛ سرور و کلید در Secret می‌مانند.
- برنامه `SupportConsole` را می‌توانید در تنظیمات به این exe اشاره دهید (`RustDeskPath`)، و در `CustomerHelper` دیگر مرحله نصب لازم نیست.

- نسخه مشتری: دکمه و صفحه تنظیمات کاملاً غیرفعال است (تغییر سرور، ID، رمز دائمی، حساب کاربری)، اتصال خروجی ندارد و فقط ID و رمز یکبارمصرف را نشان می‌دهد.

- نسخه مشتری دارای نوار برند در صفحه اصلی است: لینک تیکت و سایت، پنجره «درباره» و تعویض زبان فارسی/English. رنگ اصلی برنامه (هر دو نسخه) نارنجی لوگوی شرکت است.
- نام فایل خروجی همان نام برنامه است، مثل `DastyarHelp.exe` و `DastyarDesk.exe`.
- فایل‌های `brand.json` برای متن‌های فارسی و انگلیسی: `company_name_fa`، `description_fa`، `description_en`، `ticket_url`.
- بخش ظاهری نسخه مشتری (کد Flutter) فقط بررسی ظاهری شده و کامپایل نشده است؛ اگر ساخت در این قسمت خطا داد، لاگ را بفرستید.
